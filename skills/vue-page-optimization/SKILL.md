# Vue 页面开发与优化

## 工作流程

1. 检查项目目录、同类页面、组件源码、组件文档和请求封装。
2. 页面需要某项功能时，先查询现有组件内部是否已经实现；已有实现必须优先使用。
3. 优先复用项目已有的布局、表格、表单、弹窗、抽屉、请求和反馈能力。
4. 配置优先放入配置文件，减少模板代码和重复逻辑。
5. 只有现有组件不支持时，才新增自定义实现。
6. 遵循项目已有的目录、命名、类型和 service 规范，不引入第二套架构。
7. 默认展示后端返回值；只有需求明确要求时才增加格式化、转换、兜底、脱敏或自定义渲染。
8. 初始化数据由页面统一请求，并通过 props 传给子组件，避免重复请求。
9. 弹窗和抽屉优先复用项目已有的实例类型和打开方式；必要时使用 `ref`、`useCompRef` 与 `defineExpose({ open })`。
10. 关键实现无法从项目代码或组件文档确认时，先向用户提问，不自行猜测或引入新方案。
11. 页面状态按职责归属：与业务编排耦合的状态由页面 hook 管理；与业务无关、简单且可局部持有的 UI 状态可由页面入口或组件持有；跨页面共享或需要持久化的状态才进入 Pinia。
12. 展示组件只通过 props、emits、defineModel 交互，不直接依赖页面 store、请求或跨组件状态；与业务无关、简单且可局部持有的 UI 状态优先使用 v-model 双向绑定，避免 prop + emit + 手动同步样板。
13. 页面入口只负责布局编排、状态连接和动作分派；复杂展示块、配置块、操作块即使无业务逻辑也应拆为独立组件，组件按单一职责拆分，仅承担布局的容器留在页面入口，不额外封装无意义组件。
14. 容器和布局组件优先使用 slots 组合业务组件，避免嵌套业务组件并逐层转发事件。
15. 页面 hook 只保留领域状态和业务流程编排，统一处理异步请求、防重复执行、竞态失效、重试和错误恢复；页面只负责触发动作。
16. 重构改变职责边界时，同步迁移测试，并覆盖成功、失败、重试、非法响应和请求失效场景。

## 验证

```bash
npx eslint --no-cache <modified-files>
git diff --check
```

Vue 页面额外执行 SFC 编译检查；项目可行时执行类型检查或构建，并区分既有问题与本次改动问题。
