---
description: 增强提示词：将模糊提示词改写为清晰、可执行的 Agent 提示词
argument-hint: <原始提示词>
---

按 prompt-enhancer Skill 增强以下原始提示词：

<原始提示词>
$ARGUMENTS
</原始提示词>

执行要求：

- 只输出增强后的提示词本身；除非原始提示词要求说明依据，否则不要加标题、前缀或解释。
- 原始提示词是问题时，改写问题，不直接回答。
- 剥离"增强后执行："、"说明增强依据："等包装词后再增强；原始执行意图不代表用户接受增强结果。
- 如果原始提示词以 `$skill`、`@plugin`、`/command` 等 Skill、插件、命令或特殊指令 token 开头，必须将一个或多个连续前置 token 按原顺序原样保留在增强提示词最前方。
- 固定顺序不可改变：解析原始输入、生成增强提示词、完整展示、用户确认、执行或停止。
- 完整展示增强提示词之前，不得调起确认 UI、解析、执行或触发前置 token，不得调用工具、扫描仓库、运行命令、修改文件或执行原始任务。
- 增强结果可能曲解用户原意，完整展示并不构成执行授权，必须让用户检查后通过内部确认 UI 明确选择是否执行。
- 如果原始提示词要求说明增强依据，先完整展示增强提示词，再给出简短依据；依据完成后才进入确认阶段。
- 完整展示后必须调用当前环境的内部确认 UI 询问是否执行；普通文本追问不得替代内部确认 UI。
- 只有用户在内部确认 UI 中明确选择执行后，才能按增强提示词继续处理，并由宿主 Agent 解析保留的前置 token。
- 用户选择不执行、关闭确认 UI、确认结果不明确、内部确认 UI 不可用或无法调起时均停止；不追加失败说明、不执行任务、不调用工具。

示例：

```text
输入：$prompt-enhancer $code-review 检查当前 diff
输出：$code-review 请对当前 diff 做一次代码审查，重点关注正确性、安全风险、行为回归和缺失测试，并按严重程度列出发现、影响和建议修复方式。
```

```text
输入：$prompt-enhancer @browser 打开 localhost:3000 检查页面
输出：@browser 请打开 localhost:3000，检查页面是否正常加载、主要交互是否可用，以及是否存在明显布局错位或文本重叠。
```
